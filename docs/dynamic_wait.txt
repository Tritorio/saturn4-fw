DYNAMIC WAIT AFTER RETRACT (idea 8.11, static RE + live read 2026-10-19, V1.5.9 chitu)
============================================================================================
Goal (user): start the UV exposure as soon as the resin has settled after the retract, instead of
after a fixed wait. Data: docs/force_report.html (settling 24 s at layer 4 -> 1 s at layer 15).

HOW THE APP WAITS (func 0x7cfb4 = print-step handler, called again and again by the print loop)
- No sleep: a polled check. r4 = print struct (P below).
    0x7c368  P+0x318 (u64) = now_ms(); P+0x30b (u8) = 2          -> wait starts (after the retract)
    0x7d020  state byte P+0x30b == 2 -> 0x7d3ec:
    0x7d3ec  if machine[0x39fa30+0x188] > 0.1 and layer P+0x2ac < [[0x2fda88]+8]+0x34:
                 s16 = machine+0x188 * 1000          (bottom-layer rule; machine+0x188 = 0.0 here
                                                       -> never taken on this printer)
             else s16 = P+0x25c (float, ms)
    0x7d44c  if (now_ms() - P+0x318) > s16 + P+0x250 (float, ms):
                 log "printer start exposure %llu"    (0xd0964, logger)
                 P+0x30b = 0, log "cs1237_recoder_start 0", 0x81228(P+0x380,0), 0x832b8() = exposure
             else return (checked again on the next pass)
- now_ms() = 0xd2db0: clock_gettime(CLOCK_MONOTONIC_RAW) in ms.
- The log line is written BEFORE the exposure calls.

WHERE P IS
- P = *(uint32_t *)0x2eb6d8  (= global object 0x2eb1c0 + 0x518; written at 0x3641c/0x36424 and
  0x43608/0x43ac0, read by ~100 functions). Live 2026-10-19: P = 0x59b258 (heap).
- Per-layer block P+0x220.. (current layer), P+0x260.. (next): +0x220 7.7, +0x228 0.05,
  +0x248 PWM 255, +0x24c exposure 3300 ms, +0x250 0, +0x254 1000, +0x258 0,
  +0x25c 24000 = WAIT AFTER RETRACT (ms). Names (2026-10-21, the app's "execute:" log format 0x26c694):
  +0x24c exposure_time, +0x250 light_off_time, +0x254 rest_time_before_lift (delay between the end of the
  exposure and the lift), +0x258 rest_time_after_lift, +0x25c rest_time_after_drop. Checked: the running print ("Piramidi 3x") rests
  ~26 s per layer (24 s + end of the move).
- Live at the dump: P+0x30b = 2 (waiting), P+0x2ac = 44 (layer), P+0x318 = 10269178 ms
  (3-5 s before the dump, uptime 10272 s).

PLAN (not built): set a long wait in the slicer (= the maximum). libsgtap watches P: state 2 with
a new P+0x318 = a new wait; keep the original P+0x25c; when the force has settled (and a minimum
time passed) write P+0x25c = elapsed - P+0x250 (aligned float store, atomic). The app's own next
pass then starts the exposure through its own code. After the wait (state != 2) write the original
value back if P+0x25c still holds ours. Nothing is blocked, no app lock is touched, the wait can
only get SHORTER than the slicer's. Guard: code-word check like sgheat (0x7c368.., 0x7d3ec..,
0x7d448 vldr s16,[r4,#0x25c], 0x7d44c..) + kill switch file. Bottom-layer rule: if
machine+0x188 > 0.1 the app ignores P+0x25c for the bottom layers -> no dynamic wait there.
User 2026-10-19: bottom layers are usually 2-3, so the bottom-layer rule does not matter. Those
layers never settle anyway (report: layers 1-3) -> they would run to the maximum wait.

SETTLING RULE (agreed with the user 2026-10-19, mockup G on the dashboard canvas)
- Settled = force gradient below 1 g/s for at least 1.0 s (window adjustable 0.6-3 s) and no longer
  falling (the fast recovery after the move is over; a slow steady drip from a plate leaving the
  resin still counts as settled). Absolute level not used (buoyancy / part weight only shift it).
- Minimum wait 1.0 s (user). Maximum = the slicer's wait after retract (only ever shortened).
- Evaluate on every gauge reading (~5/s), not on the 0.5 s writer tick.
- CSV: wait_s (wait used) + wait_end (settled | max | off).
- BEFORE BUILDING: replay the rule offline on the logged force curves (Piramidi 3x, 0-11.5 mm,
  covers the plate leaving the resin) and tune it.

IMPLEMENTATION (2026-10-20, image 22, mods/src/sgtap/sgwait.c; UI = mockup G + I)
- Own thread in libsgtap, 20 Hz. A wait starts when P+0x30b == 2 with a new P+0x318 that is < 3 s
  old (the printer state word is NOT used: it may read 3 during a print). Per wait: original
  P+0x25c/P+0x250 kept; bottom layer = P+0x2ac < [[0x2fda88]+8]+0x34 -> hands off (slicer wait).
  Sanity: wait < 1 h and P+0x2ac within +-1 of the app log's layer, else hands off.
- Settled = |least-squares slope| of the readings of the last WIN s (all inside the wait, >= 3
  readings) < GRAD g/s, and elapsed >= MIN and >= WIN. Then P+0x25c = target - P+0x250 (only if
  shorter than the original); restored when the wait is over if still ours.
  Replay of this exact rule on the 12x raw capture (layers 45-114): all 69 settled, median force
  change after the trigger 2 g (worst 31 g, layer 51); waits 1193 s -> 205 s.
- Wait & heat: heater mode word 0x2fed38+0x114 = 2 (what the app's stage3 code does via 0x8aae0;
  RE 0x79d84: heat start = stage3 start + machine+0x284 (1000 ms), end = planned end - 1000 ms;
  the heater thread 0x89f28 keeps the thermostat: print target +0x198, allowed error +0x1a8/+0x1ac,
  single-cycle limit +0x1a4 min) at the wait start if the previous non-bottom wait (settle time,
  without the +1 s) was >= 3 s and "heating during print" is on and the heater is ready and the
  mode is 0. Off when settled (exposure released 1 s later), at slicer wait - 1 s, and always when
  the wait ends. Bottom layers: heated until slicer wait - 1 s if that wait > 3 s.
- Settings <csvdir>/WAIT "DW WH GRAD WIN MIN" (absent = off), command "wait ..." via sgwebd.tcl
  (same ranges, WH needs DW), live.json "wait":{dw,wh,grad,win,min,heat_ok,active,layer,bottom,
  heating,el,max,g,prev,n,ns,nm,nh,saved,last:[[layer,used_s,end 0 settled|1 max|2 off,heated]]},
  CSV columns wait_s,wait_end,heat_w. Kill switch /customer/mod/sgwait_disable.
- Tested: sgwebd validation on the printer (test instance, 12 cases); page layout desktop + 390 px
  (headless Chrome, fake live.json); libsgtap builds clean. NOT yet tested inside the app.
